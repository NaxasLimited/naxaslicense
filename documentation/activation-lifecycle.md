# Activation lifecycle
Pending requests expire after the configured TTL. An administrator assigns an eligible active matching license, then approves transactionally or rejects/expires it. Approval creates one activation and encrypted signed entitlement. Status proof is the token plus installation UUID. Rejected, expired, completed and cancelled are terminal; approval cannot repeat. Delivery currently retains the encrypted approved entitlement to tolerate interrupted responses; an explicit acknowledgement endpoint is deferred until Buildora supports it, so approved polling remains bounded by rate limits and license lifecycle.
